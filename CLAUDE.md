# CLAUDE.md — project context for AI coding agents

Context for continuing Vita with an AI coding agent (Claude Code, Cursor, etc.). Human docs: [README](README.md) · [ARCHITECTURE](ARCHITECTURE.md) · [ROADMAP](ROADMAP.md) · [CONTRIBUTING](CONTRIBUTING.md). No secrets here.

## What this is

A native **iOS 26 / SwiftUI / Swift 6** educational peptide-tracking app. SwiftData local-first store; Claude Opus 4.8 (raw `URLSession`, no SDK) for protocol generation, grounded streaming chat, and lab-image reading. Single app target. **Educational only, never medical advice** — keep that framing in every AI/dosing/lab surface.

## Build / run / test loop

The Xcode project is **generated by XcodeGen** from `project.yml` and is gitignored — regenerate after any file/`project.yml` change.

```bash
xcodegen generate
xcodebuild -project Vita.xcodeproj -scheme Vita \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test     # 159 tests
```

- Local config: `cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig` (key + `DEVELOPMENT_TEAM`). The app runs with **no key** (rule-based fallback) and tests/screenshots use `VITA_CLAUDE_STUB=1`.
- Simulator demo/screenshot flags need the `SIMCTL_CHILD_` prefix on `simctl launch` (e.g. `SIMCTL_CHILD_VITA_DEMO_STACK=1`). Flags: `VITA_DEMO_STACK`, `VITA_CYCLE_DEMO`, `VITA_DIARY_DEMO=1|2`, `VITA_LABS_DEMO`, `VITA_OPEN_SETTINGS`, `VITA_OPEN_DETAIL=<slug>`, `VITA_TAB=today|stack|diary|chat`, …
- Device build: `-allowProvisioningUpdates`; `xattr -cr .` first or codesign fails with "…detritus not allowed". Free Apple accounts can't provision HealthKit/Time-Sensitive (strip them from `Support/Vita.entitlements` for a sideload).

## Where things live

- `Vita/Data/` — models, services, **pure engines** (`ScheduleService`, `ReconstitutionCalculator`, `StreakService`, `DiarySeries`, `LabService`), and `Data/Claude/` (the only network surface).
- `Vita/Features/<Surface>/` — SwiftUI views per tab/flow.
- `Vita/DesignSystem/` — `VT.*` tokens, typography, motion, haptics, shared components.
- Tests in `VitaTests/` (pure logic + services).

## Conventions (do these)

- **Keep `Data/` engines pure and tested; views thin.** Add unit tests for new logic.
- **Design system only:** `VT.*` tokens + shared components (`PillToggle`, `ScreenHeader`, `vtCard()`, `CharcoalPillButton`, `vtLead`). No raw system colors. Liquid Glass on nav/controls/sheets, never content cards. Tabular figures on changing numbers. Every component ships a `#Preview` on cream with real data.
- **No em dashes in user-facing strings** (guard test enforces it). Calm, educational voice; keep disclaimers.
- **Scheduling is derive-live** — never materialize dose events. Cycles = a gate in `isDueDay`; titration = `activeDose(on:)`.
- **Never trust model output** — validate against the catalog (drop unknown slugs, clamp doses); identity/units come from the catalog. The app always works without a key (stub/fallback).

## Gotchas (learned the hard way)

- SwiftData: set a relationship **only after** `context.insert`; **retain** the in-memory `ModelContainer` in tests or it traps.
- `PreferenceKey.defaultValue` must be `static let` under Swift 6.
- SourceKit often shows false "Cannot find 'VT' in scope" cross-file — trust `xcodebuild`, not per-file diagnostics.
- Opus 4.8 request constraints: no `temperature/top_p/top_k`, no `thinking` with forced tool-use, `max_tokens` required (see `AnthropicClient`).
- Prompt caching has a minimum length; the labs system prefix is below it (so `cache:true` is a harmless no-op there).
